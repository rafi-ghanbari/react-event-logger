# Contributing to Event Logger

First off, thanks for taking the time to contribute! 🎉

The following is a set of guidelines for contributing to React Event Logger. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

## How to Contribute

### Reporting Bugs
This section guides you through submitting a bug report.
- **Use a clear and descriptive title** for the issue to identify the problem.
- **Describe the steps to reproduce the problem** in as much detail as possible.
- **Include screenshots or animated GIFs** which show you following the reproduction steps.

### Submitting Pull Requests
1.  Fork the repo and create your branch from `main`.
2.  If you've added code that should be tested, add tests.
3.  Ensure your code follows the existing style patterns.
4.  Issue that pull request!

## Commit Message Guide

We follow the **Conventional Commits** specification. This leads to more readable messages that are easy to follow when looking through the project history.

### Format
`type(scope): subject`

### Common Types
- `feat`: A new feature
- `fix`: A bug fix
- `docs`: Documentation only changes
- `style`: Changes that do not affect the meaning of the code (white-space, formatting, etc)
- `refactor`: A code change that neither fixes a bug nor adds a feature
- `perf`: A code change that improves performance
- `chore`: Changes to the build process or auxiliary tools and libraries

### Example Commit Messages

Here are some real-world examples you can use for inspiration:

1.  **Feature**: `feat(sidebar): add real-time search filtering logic`
2.  **Fix**: `fix(modal): resolve z-index issue on mobile devices`
3.  **Docs**: `docs: update installation instructions in README`
4.  **Style**: `style(event-item): improve hover state contrast`
5.  **Refactor**: `refactor(context): optimize event selection reducer`
6.  **Performance**: `perf: implement memoization for event list rendering`
7.  **Chore**: `chore: update date-fns dependency to v4.1.0`

By following these conventions, we ensure a clean and professional commit history for the project.
